# 常见 Bug

> 记录真实踩过的坑。格式：现象 / 原因 / 解决。

## Bug
- 现象：程序一运行就崩溃（"Segmentation fault"），或者结果莫名错误。
- 原因：**数组越界**或**野指针**——访问了不属于自己的内存（如 `int a[5]` 却访问 `a[5]`，或指针没初始化就 `*p = 10`）。C 不检查越界，出错的是别处的数据，所以最难查。
- 解决：写循环时确认 `i < n`（不是 `<=`）；指针一律先 `NULL` 再判断；怀疑越界时把数组开大一点 + 在关键处打印调试。

## Bug
- 现象：输入数字时程序直接跳过输入、或读进来是 0 / 垃圾值。
- 原因：**scanf 漏写 `&`**。`scanf("%d", x)` 传的是 x 的值，不是地址；scanf 需要地址才能写进去。
- 解决：检查每个 `scanf` 的变量是否都写了 `&`（指针变量、数组名除外，它们本身就是地址）。

## Bug
- 现象：`5 / 2` 结果居然等于 2，不是 2.5。
- 原因：**整数除法截断**——两个 int 相除结果还是 int，小数部分直接丢掉。
- 解决：想让结果是小数，把一边转成浮点：`5 / 2.0` 或 `(double)5 / 2`；算平均值时尤其容易踩。

## Bug
- 现象：两个内容相同的字符串 `if (s1 == s2)` 判出来是「不相等」。
- 原因：**字符串不能直接比**——`s1`、`s2` 是地址（字符数组首地址），`==` 比的是地址而不是内容。
- 解决：用 `strcmp(s1, s2) == 0` 判断内容相等；需要 `#include <string.h>`。
